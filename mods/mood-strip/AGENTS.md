# Notes for the AI building this mod

This folder is a finished, working Claude Code mod: a plugin whose hooks module (`hooks/register.tsx`) draws a full-width colored strip above the prompt box and keeps it in step with the session. It only runs inside Claude Code (the desktop app or the terminal). The person you're helping may never have coded, so use plain words, short answers and sensible defaults, and tell them what you picked.

## Files

- `.claude-plugin/plugin.json`: name, version, description.
- `hooks/hooks.json`: points to `register.tsx`.
- `hooks/register.tsx`: everything the strip does. `VERSION` here must match `plugin.json`.
- `types/index.d.ts`: the saved values (atoms) the hooks read and write.
- `tests/`: the tests (one file per area; `session-words.test.tsx` covers what counts as your words).

## Check and test

From this folder (on Windows, `claude.cmd` instead of `claude`):

```
claude plugin validate .
claude plugin test .
```

`validate` warns that `CLAUDE.md` at the plugin root isn't loaded as project context. That's expected: `CLAUDE.md` and `GEMINI.md` are here for AI coding apps opened in this folder, not for the installed mod.

Every test must pass before a change is installed. Tests use the testing kit's fake clock and fake store (`mock.clock`, `mock.store`), never the person's real settings or sessions.

## To see it while building

Load the folder as a development mod that reloads on change, and turn off any installed copy of `mood-strip` first, or the old copy keeps drawing and the new one seems missing. Development mods load when a reply ends; a new session always picks them up. `/mood` names the running version, and `/mood demo` plays every look.

## Rules the desktop app taught us

- **Colors:** the desktop app does not paint raw color codes on `Box` or `Text` (you get a white bar). Use the theme's named colors there, or draw with `Svg`, which it paints exactly. The terminal uses `Box backgroundColor` and `Text`.
- **No flashing:** redraw the `Svg` only when what it shows changes. Do fades inside the picture with SMIL (`<animate values keyTimes dur begin="-Nms" fill="freeze">`), never by redrawing every second.
- **Full width:** give the `Svg` component `width={4000}`, and the picture `width="4000"` plus `style="width:100%"`. Without it the picture fills only part of the space.
- **Clicks:** only `Button` takes presses, and a `Button` can't hold an `Svg`. The strip has nothing to click.
- **Privacy:** never put the person's own message text on the strip, and never store it. A test checks this. Every name shown or kept (file, helper, skill, tool, plan step) must pass `isPrivate`: no path or address (a slash or a look-alike of one such as "∖" or "᜵", "~", a drive letter, a scheme such as file: or https:, a home folder spelled out), no secret, no private subject (the health, money and identity words the thinking line drops, as a part of a joined name, and the longer ones such as mortgage, salary, payroll, medical, insurance, rehab and taxes also inside a name written as one word: "mortgagecalc"; payslip, medicare and creditscore the same way; and tax, ssn and hiv at the start or end of a joined name part: "taxform", "mytax", "userssn", "ssnlookup", "hivtest", but not in the middle, so "syntax", "classname" and "archive" stay), no letter of any script but Latin once accents are off (Greek, Cyrillic, Cherokee, Lisu, Japanese and the rest: many pass for Latin letters or for a slash, so the rule is the script, not a list), and no word the person typed anywhere in the session (any one distinctive word counts, not only four in a row, even a one- or two-character code name, also glued into a name: "QX" in "QXLoader", "qxloader", "loaderqx" or "myqxloader", "Bob" in "newbob" or "mybobcard", spelled with look-alike digits ("0pal", "8ob"), phonetic look-alike letters ("ɵpal"), umlauts written out ("Mueller" for "Müller", both ways), or in Latin letters for a word typed in Greek or Cyrillic ("Maria" for "Μαρία", in every combination of the usual spellings of each letter or group, up to 64 per word: Cyrillic й as y, i or j; ий as iy, y, i, ii or ij; ия as iya, ia or ija; ья as ya, ja, ia or iya; ю as yu, iu or ju; я as ya, ia or ja; кс as ks or x; ё as e, yo or jo; Greek χ as ch, h or kh; γγ as gg or ng; ου as oy or ou; αυ and ευ as ay, av or af and ey, ev or ef; ος as os or ios; γιω as gio, geo, yio or yo; and γι at the start of a word as gi, yi or y; so Алексей hides aleksey, alexey, aleksei and alexei, and Ксения hides ksenia and xenia. A word with more combinations than 64 (or with letters the lists do not cover) is hidden by its plain spelling and by every letter on its first, second, third option; a rare spelling can still show. Typed as a letter and a mark apart, й and ё are put back together before the lists are used), "ue" read as "u" ("Juergen" hides "jurgen"), and a code name with its number left off ("Falcon" of "Falcon9", the number any Unicode digit, not only 0 to 9); a short word is not looked for inside an ordinary word, so "Al" does not hide "local"). Only ordinary words are exempt: everyday English and the common words of files and tools, such as app, index, test, src, package, readme, config, main. Never on that list: days, months, places, country and region codes (uk, eu, gb), first names and nicknames, also those that are words too (will, may, max, chance, ty, em, mac, red, ai, min, dev); a test checks it against a set of several hundred. A few everyday words are also surnames (long, fields, page) and stay, and so do the core little words that are also codes (in, us, me, or, ok) and the file endings md and id. Also left on the list, on purpose: the short words that double as codes (qa, tv, pr, th, hi, oh, on, mb, st and similar). Their everyday meaning (a TV, a PR, "hi", "oh", "on", "5th", MB, "St.") is far more common than a private code, and hiding them would hide most steps and files; a test pins this. What the person typed means every message (also one sent while Claude works, taken in at `prompt.submit`, or found in a tool result as "The user sent the following message"), what follows any slash command (`command.run`), every answer to `AskUserQuestion` or `ExitPlanMode` (without the question or plan Claude wrote), and what they said when they declined a step or a hook denied it. The words live only in the module's memory (`heard`), added to and never replaced; something too long to remember whole turns names off in every session this copy of the mod serves, until the mod loads again (and again after that load if the transcript read back holds it). Anything that fails shows as the generic label. Text is cleaned first (invisible characters, markup, full-width letters) and compared folded (accents off, Latin look-alikes such as "ı" or "ø" as the plain letters), and every check runs on the cleaned form and on the original.
- **Commands:** never the whole command line (it can hold keys, passwords or private paths). A well-known program shows by name ("Running npm"); anything else is "a command". Text written into files (heredocs, here-strings) is never read as a command, and neither is a message handed over as `"$(cat <<'EOF' … EOF)"` with a quoted marker, so the usual commit reads "Snapshot saved". A command with several parts (`&&`, `||`, `;`, a pipe, `&`) is not read part by part: only a single command, or a chain of `&&` that succeeded, counts as a test, build, push or commit result; anything else is "Ran a command". Tests piped on (`npm test 2>&1 | tail`) show "Running the tests…", then "Tests finished", never a pass or a fail.
- **Builds:** "Building…", "✓ Build passed", "✗ Build failed, fixing…"; the recap says "build passing". A build never counts as a test.
- **Tool names** read like "Using read file". Claude Code's own tools show by name; any other tool's name gets the same check as a file's and is "a tool" when it fails.
- **Thinking line:** on by default (since 0.8.2). The `showThinking` option ("Show Claude's thinking") defaults to `true` in `plugin.json`; its description warns that thinking can put private details on screen (names, health, money) and says to turn it off when streaming or sharing the screen. The hook reads it with `isThinkingSetOn`: on unless the setting is clearly off (`false`, the text false, off, no or 0 in any case, or the number 0); a missing or odd value counts as on. The filters are the same on or off. When on: `“sentence…”` at the start of the middle part, complete sentences only, up to 60 characters. Drop any sentence that echoes the person's own words, says "the user", quotes something, holds a path, URL, email or token, has 5 or more digits, looks like a phone number or street address, uses health, money, legal or identity words (0.8.2 added blood, patient, doctor, dr, clinic, hospital, invoice, payment, paid, unpaid, bank statement, iban, routing number, lawyer, attorney, legal memo, complaint, settlement, home address, a production machine such as orion-db-prod or "prod host", and "keys for"; "routing" and "key" alone stay visible as everyday code words. The same words also hide a file, helper, skill or step name, also inside a joined one: "invoice-total.ts" shows as "a file"), or talks about someone else or names a machine (`THIRD_PARTY`: he, she, him, his, her, hers, himself, herself; a dotted host name ending in com, net, org, io, dev, app, co, internal, local, corp, lan or a country code, but not file endings such as md, py, rs, sh; an email or phone spelled out ("dot com", "at gmail", "five five five"); "server called ..."; "live server orion"), uses the housing, legal, pay, card and health words added after the 0.8.2 review (rent, tenant, eviction, custody, arrested, court, fired, income, earns, wages, bonus, refund, overdrawn, card ending, wire transfer, bounced, mental health, psychiatric, addiction, allergies, epilepsy, cholesterol, insulin, covid, heart attack, sick leave), holds a number and a street in any case ("12 elm street", "on baker street"; `ADDRESS_SHAPE_LOWER`, `ON_STREET`), or seems to hold a person's or company's name (`holdsLikelyName`; titles in any case; a dotted word of two unknown parts such as "jane.smith"; "Ruby wrote", "Swift fixed", "Page reported" and the like; code identifiers such as UserCard, TypeError and Promise.all and everyday capitalized words such as Button are not names, see `isCodeWord`; a name in lower case with no clue, like "what jane changed", is a known limit): a title (Dr, Mr, Mrs, Ms, Mx) before a capitalized word, a capitalized word past the first that is not on the `TECH_CAPS` list (GitHub, Python, React, TypeScript, Docker, Azure, AWS, JSON, SQL, CSS, HTML, npm, Node, Claude, VS Code, "I" and its short forms, and a few dozen more: keep it modest, a word missing there only hides a sentence), or a first word that is capitalized yet neither an everyday word nor an opener or "-ing" verb of coding work (`OPENERS`). When in doubt it drops the sentence and the strip shows "Thinking…". To turn it off: `/config` (the option is a row) or `claude plugin configure mood-strip@apps`, then `/reload-plugins`.
- **Private-looking names:** file, helper, skill and step names that look private fall back to "a file", "a helper", "a skill" or "Step N of M".
- **Long text:** each part caps at about 48 / 75 / 48 characters, cut at a word with "…", with a soft fade at its right edge; never mid-letter.
- **Done:** teal holds for the whole 3 minutes, then fades to the time-of-day colors in the last 2.5 seconds.
- **After a reload:** step, file, helper and tool names stay hidden until the next message the person types to start a turn (an app note such as `<task-notification>`, an empty turn or a message sent into a running turn does not count), unless the session's own transcript is shown to be whole: `$.session.messages()` under the engine's 4,096-message limit, no row marked as a summary or compaction (a field or type naming one) or worded like one, and exactly as many messages of the person's in it as `$.session.turns()` counts. Anything else is not trusted. Its words (messages, answers, declines) are taken in either way. Each session (by `$.session.id()`) is known on its own; words heard in any session stay hidden in all of them.
- **`/mood`** also reports "Screen width reported: N columns".
- **Failures:** a tool the person declined or interrupted is not a failure, and neither is exit code 1 from grep, test or diff.
- **Endings:** "✓  Done in X", "■  Stopped after X" (stop pressed), "✗  Ran into an error after X" (API error), "■  Claude declined after X" (refusal). The step count shows once. Background work shows "Tests started" or "Helper started".
- **Terminal:** no fades and no amber drift there; paint each mood's color at once.
- **Plans:** the plan tool, TodoWrite and TaskCreate/TaskUpdate all feed the dots. Labels are made safe before they are saved (an unsafe one is saved as an empty label), and a plan belongs to the task that is running (`Plan.owner`), so a late result from an older task changes nothing.
- **Keeps:** only today's counts: one `day:YYYY-MM-DD` entry for today (tasks, workMs, nothing else) in the mod's own store, and the last task in the session's state. Every other `day:` key is deleted at session start (so if Claude Code wasn't running at midnight, the first launch on the new day clears them), when the date changes (the minute tick notices it, also in a session left idle past midnight) and after each saved task, and a last task from an earlier day is cleared once its Done look is over. The tick also reads the store again, so tasks another session finished show up. The usual task length is today's average, or 3 minutes until there are 2 tasks. At session start every name held from an earlier version or from before a reload (plan steps, the last task's file, the running task's trail, files and helpers) is replaced by a generic one. Wherever the docs mention storage, say exactly this: "It keeps only today's counts (tasks, work time, the last task), on your computer, and clears them when the day changes: at midnight, or, if Claude Code wasn't running then, the first time it starts on the new day. It never keeps your messages." plus where the store file is and that it can be deleted.
- **Demo:** `/mood demo` plays 25 looks between tasks only; during a task it answers "A task is running, so the demo would hide what Claude is doing. Try /mood demo between tasks." It can be rerun safely, and a real turn ends it. `/mood` says when the demo is playing.
- **Contrast:** words on every mood color pass 4.5 to 1 at full strength (working #726BC7, long #A66815, waiting #C34D74, win #54831D, stuck #D14544, done #198664, stopped #C6522C).
- **Escaping:** file names and thinking text go into the picture's XML, so escape `<`, `&` and quotes.
- **Streaming:** the `turn.step` hook passes every chunk on unchanged, watches only the main conversation (`agentId` undefined), and must never let a failed store write stop the stream.

## Rules for working

- **Build changes in a copy** and swap them in only when `validate` and `test` pass.
- **Never fail silently.** Every hook passes its event on even when the strip can't update, and the problem is saved as `lastError`, which `/mood` shows as "Last problem". Its details pass the same checks as a name, again at start and when shown (an earlier version checked them less); until the session's words are known only the place shows.
- **To change something,** follow `KIT.md`, section 7 ("Make it your own"). One change at a time, tested before the next.
